   347→### Paper 2: Risk-Aware Reinforcement Learning for Trading
   348→
   349→**Key Papers**:
   350→- "Risk-Aware Deep RL for Dynamic Portfolio Optimization" (arXiv:2511.11481) — PPO with Sharpe ratio reward + drawdown/volatility constraints
   351→- "Risk-Aware RL Reward for Financial Trading" (arXiv:2506.04358) — Multi-objective reward function blueprint
   352→- "RiskawareTrader" (Springer, 2025) — RL-based portfolio with risk constraints
   353→
   354→#### Key Findings & Reusable Patterns
   355→
   356→| Technique | Description | Application |
   357→|-----------|-------------|-------------|
   358→| **Sharpe-Ratio Reward** | Reward = (return - risk_free) / volatility | Better than pure return maximization |
   359→| **Maximum Drawdown Penalty** | Penalize drawdowns in reward function directly | Prevents catastrophic losses |
   360→| **Volatility Constraint** | Hard constraint on portfolio volatility in action space | Risk budgeting |
   361→| **Multi-Objective Reward Shaping** | Combine return, risk, turnover, transaction costs | Realistic trading optimization |
   362→| **Over-Conservative Policy Problem** | Too much risk penalty → agent learns to hold cash | Balance is key — need adaptive risk weighting |
   363→
   364→**Key Insight**: The risk-aware RL paper found that **over-conservative policies** emerge when risk penalties are too strong. The agent stabilizes volatility but sacrifices risk-adjusted returns. This suggests we need **adaptive risk weighting** that adjusts based on market regime.
   365→
   366→```python
   367→class RiskAwareReward:
   368→    """Multi-objective reward with adaptive risk weighting"""
   369→    def __init__(self, risk_aversion=1.0, regime_detector=None):
   370→        self.risk_aversion = risk_aversion
   371→        self.regime_detector = regime_detector
   372→    
   373→    def compute(self, portfolio_state, action):
   374→        base_reward = self._return_component(portfolio_state)
   375→        risk_penalty = self._risk_component(portfolio_state)
   376→        turnover_cost = self._turnover_component(action)
   377→        
   378→        # Adaptive risk weighting based on regime
   379→        if self.regime_detector:
   380→            regime = self.regime_detector.predict(portfolio_state.features)
   381→            adaptive_aversion = self.risk_aversion * regime.risk_multiplier
   382→        else:
   383→            adaptive_aversion = self.risk_aversion
   384→        
   385→        return base_reward - adaptive_aversion * risk_penalty - turnover_cost
   386→```

   411→### Paper 4: Probabilistic Forecasting (Conformal Prediction, Bayesian Methods)
   412→
   413→**Key Papers**:
   414→- "Conformal Predictive Portfolio Selection" (arXiv:2410.16333) — CPPS framework for portfolio selection with prediction intervals
   415→- "Probabilistic forecasting methods review" (arXiv:2511.05523) — Evolution from Bayesian to distribution-based to conformal approaches
   416→
   417→#### Key Findings & Reusable Patterns
   418→
   419→| Technique | Description | Application |
   420→|-----------|-------------|-------------|
   421→| **Conformal Prediction Intervals** | Distribution-free prediction intervals with coverage guarantees | Replace point predictions with confidence intervals |
   422→| **CPPS (Conformal Predictive Portfolio Selection)** | Portfolio selection using conformal prediction intervals | Risk-aware portfolio construction |
   423→| **Quantile Regression** | Predict multiple quantiles instead of point estimates | Better uncertainty quantification |
   424→| **Bayesian Updating** | Online Bayesian updating of return distributions | Adaptive risk models |
   425→| **Coverage Guarantees** | Conformal methods guarantee marginal coverage | Regulatory compliance for risk models |
   426→
   427→**Critical Pattern — Conformal Prediction for Trading**:
   428→```python
   429→class ConformalPredictor:
   430→    """Distribution-free prediction intervals for price forecasts"""
   431→    def __init__(self, base_model, alpha=0.1):
   432→        self.base_model = base_model
   433→        self.alpha = alpha  # 1 - coverage level
   434→        self.calibration_scores = []
   435→    
   436→    def calibrate(self, X_cal, y_cal):
   437→        """Compute nonconformity scores on calibration set"""
   438→        predictions = self.base_model.predict(X_cal)
   439→        self.calibration_scores = np.abs(y_cal - predictions)
   440→    
   441→    def predict_interval(self, X_new) -> tuple[float, float]:
   442→        """Return prediction interval with coverage guarantee"""
   443→        point_pred = self.base_model.predict(X_new)
   444→        quantile = np.quantile(self.calibration_scores, 1 - self.alpha)
   445→        return (point_pred - quantile, point_pred + quantile)
   446→```

   458→| Technique | Description | Application |
   459→|-----------|-------------|-------------|
   460→| **SHAP for Global Feature Importance** | Model-agnostic feature attribution for overall model behavior | Which factors drive predictions? |
   461→| **LIME for Local Explanations** | Explain individual predictions | Why did we BUY this stock today? |
   462→| **Collinearity Warning** | Both SHAP and LIME struggle with correlated features (common in finance) | Use conditional SHAP or tree SHAP for correlated features |
   463→| **Explanation Stability** | LIME explanations are unstable across runs | Prefer SHAP for production; use LIME only for ad-hoc exploration |
   464→| **Feature Importance as Risk Signal** | Sudden changes in feature importance = model drift | Model monitoring in production |
   465→
   466→**Key Insight**: SHAP is more reliable for production use (stable, theoretically grounded). LIME is useful for quick exploration but unreliable for audited decisions. In finance, where correlated features are the norm, use **TreeSHAP** for tree models and **KernelSHAP with conditional expectations** for other models.

   489→**Critical Pattern — Deterministic Policy Layer**:
   490→```python
   491→class DeterministicPolicy:
   492→    """Wraps probabilistic model outputs with deterministic policy"""
   493→    def __init__(self, model, rules):
   494→        self.model = model
   495→        self.rules = rules  # deterministic business rules
   496→    
   497→    def decide(self, market_state) -> TradeDecision:
   498→        # Get probabilistic prediction
   499→        prediction = self.model.predict(market_state, temperature=0)
   500→        
   501→        # Apply deterministic policy rules
   502→        if prediction.confidence < self.rules.min_confidence:
   503→            return TradeDecision(action="HOLD", reason="Below confidence threshold")
   504→        
   505→        if market_state.volatility > self.rules.max_volatility:
   506→            return TradeDecision(action="HOLD", reason="Volatility regime filter")
   507→        
   508→        # Deterministic position sizing
   509→        size = self.rules.kelly_fraction * prediction.edge / prediction.variance
   510→        
   511→        return TradeDecision(
   512→            action=prediction.action,
   513→            position_size=min(size, self.rules.max_position),
   514→            reason=prediction.reasoning
   515→        )
   516→```

   530→|-----------|-------------|-------------|

   532→| **Confidence-Based Escalation** | Only escalate to human when model confidence is low | Reduce human fatigue |
   533→| **AI-in-the-Loop** | Human proposes, AI validates/rejects | Alternative to traditional HITL |

   535→| **Alert Fatigue Prevention** | Too many human escalations → humans ignore all alerts | Smart filtering of escalations |
   536→
   537→**Critical Pattern — Confidence-Based Escalation**:
   538→```python
   539→class EscalationPolicy:
   540→    """Route decisions between autonomous and human-approval paths"""
   541→    
   542→    AUTONOMOUS = "autonomous"     # High confidence, low risk
   543→    NOTIFY = "notify"            # Medium confidence, medium risk
   544→    ESCALATE = "escalate"        # Low confidence or high risk
   545→    BLOCK = "block"              # Forbidden under current conditions
   546→    
   547→    def route(self, decision: TradeDecision, portfolio: Portfolio) -> str:
   548→        # Risk-based routing
   549→        if decision.position_value > portfolio.total_value * 0.1:
   550→            return self.ESCALATE  # Large position needs human approval
   551→        
   552→        if decision.confidence > 0.8 and decision.risk_score < 0.3:
   553→            return self.AUTONOMOUS
   554→        
   555→        if decision.confidence > 0.5 and decision.risk_score < 0.5:
   556→            return self.NOTIFY
   557→        
   558→        if portfolio.current_drawdown > 0.15:
   559→            return self.BLOCK  # Circuit breaker
   560→        
   561→        return self.ESCALATE
   562→```
